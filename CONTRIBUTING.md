## Reporting a bug

[Open an issue](https://github.com/allenguarnes/vomd/issues) with:

- your VOMD version (`vomd --version`) and OS, and on Linux whether you use X11 or Wayland;
- what you did, what you expected, and what happened instead;
- the Markdown file (or a small part of it) that shows the problem, if you can share it.

## Getting set up

You need:

- **Rust** through [rustup](https://rustup.rs). The toolchain is pinned in `rust-toolchain.toml`,
  and rustup installs it on the first build.
- **[just](https://github.com/casey/just)** (optional) for the shortcuts below.
- **Windows:** the Visual Studio Build Tools with the "Desktop development with C++" workload.
- **Some checks only:** a display (the performance budgets) and docker (the clipboard and
  packaging checks).

```sh
git clone https://github.com/allenguarnes/vomd
cd vomd
cargo run --release -- README.md
```

## Everyday commands

| Command | What it does |
|---|---|
| `just ci` | Everything CI checks: formatting, clippy for every feature set, the tests, Windows and macOS compile checks, and the size budget |
| `just test` | The tests, with the default features and two smaller feature sets |
| `just clippy` | Clippy for every feature set, warnings as errors |
| `just budgets` | Every performance budget, on release builds (needs a display) |
| `just bless` | Regenerate the golden images |
| `just fuzz <target> [seconds]` | Fuzz one target |

The macOS and Windows compile checks (`just check-other`) need
`rustup target add x86_64-pc-windows-gnu aarch64-apple-darwin`.

## Tests

`cargo test --workspace` runs everything. A few kinds of tests need a word of explanation:

- **Golden images** (`tests/golden.rs`) render documents from `fixtures/` without a window, using
  only the built-in fonts, and compare them with `tests/golden/*.png`. When a change to the
  rendering is intended, run `just bless` and look at every changed image before committing it.
  On a mismatch, the actual image and a diff are written to `target/golden-out/`.
- **Image memory tests** (`tests/image_memory.rs`) are slow under `cargo test`. `just images`
  (`cargo xtask images`) runs each one in its own process, as many at once as you have CPUs;
  `-j N` sets the number and `--runs K` repeats them.
- **Clipboard** (`just clipboard`): selects, copies and pastes with the real `xclip`, `xsel` and
  `wl-paste`, against Xvfb and a headless sway in containers. Needs docker.
- **No network without consent** (`just netns`): checks that VOMD makes no network request until
  you press `I`. Needs a display and user namespaces.

Test documents live in `fixtures/`; `fixtures/FIXTURES.md` lists what each one is for. The large
ones are generated by `cargo xtask fixtures`.

Tests that wait on threads should wait for the condition they need, not sleep for a fixed time:
CI runners are slower than your machine, and timing-based tests fail there.

## Performance budgets

VOMD has hard budgets for start-up time, scrolling, memory, idle CPU and binary size, and CI
fails when one is missed.

- `cargo xtask size` checks the size of the release binary.
- `cargo xtask budgets` measures everything else against release builds. It needs a display; on
  a Wayland desktop, run it under X11 (`WAYLAND_DISPLAY= cargo xtask budgets`), since a hidden or
  idle Wayland window may not be drawn at all.
- `cargo xtask bench [fixture]` and the programs in `examples/` (`paint_bench`, `layout_bench`,
  `parse_bench`, …) measure single parts more closely.

If your change makes VOMD bigger or slower, say so in the pull request, with numbers.

## Fuzzing

`just fuzz <target> [seconds]` runs a fuzz target from `fuzz/fuzz_targets/` on the stable
toolchain. The targets are `doc`, `image`, `anim`, `layout`, `settings` and `svg`. A nightly CI job
also fuzzes every target with AddressSanitizer. A crash leaves its input in `fuzz/artifacts/`;
add it to `fuzz/seeds/<target>/` with the fix, and add a test for it.

## Cargo features

All features are on by default. Turning some off makes a smaller binary:

| Feature | What it adds |
|---|---|
| `images` | PNG, JPEG, GIF and WebP images, animations included |
| `svg` | SVG and svgz images (needs `images`) |
| `remote-images` | Remote images, fetched with the system `curl` |
| `embed-fonts` | The built-in fonts (without it, VOMD uses system fonts) |
| `clipboard` | Selecting and copying text |
| `toc` | The contents panel |
| `find` | Find in page |

```sh
# Without SVG (SVGs show their alt text), about 4.1 MB on Linux:
cargo build --release --no-default-features --features images,remote-images,embed-fonts,clipboard,toc,find
# The smallest build: no images and system fonts only, about 3.0 MB on Linux and 1.9 MB on Windows:
cargo build --release --no-default-features
```

## Packaging

| Command | What it does |
|---|---|
| `cargo xtask dist` | The release tarball (Linux) or zip (Windows) in `dist/` |
| `scripts/pkg-build.sh` | The tarball, `.deb` and AppImage, built in a Debian 12 container as CI does (needs docker) |
| `scripts/pkg-check.sh` | Installs and runs the `.deb` and AppImage on Debian 12, Debian 13 and Ubuntu 24.04 (needs docker) |
| `just aur` | Builds and checks both Arch packages offline, without installing them (commit first) |

Releases are built by `.github/workflows/release.yml` when a `v*` tag is pushed. The release
notes are that version's section of `CHANGELOG.md`.

## Vendored crates

`vendor/` holds three crates VOMD patches, used through `[patch.crates-io]` in `Cargo.toml`:

- **resvg 0.46:** its raster images go through VOMD's decoders, and drawing can be cancelled.
- **image-webp 0.2.4:** a memory limit on a lossless image's Huffman codes.
- **simplecss 0.2.2:** an error's position found in constant time (a style sheet with many rules
  used to take time quadratic in its length).

Each one's `VOMD-PATCH.md` lists the changes and how to upgrade the crate.

## Pull requests

- Keep each pull request to one change, and add a test that fails without it.
- Run `just ci` (or at least `cargo fmt`, `just clippy` and `just test`) before opening it.
- Add a line to the `[Unreleased]` section of `CHANGELOG.md` for anything a user would notice.
- Commit subjects use `type(scope): description`, for example `fix(find): keep the match when
  the window is resized` or `feat(toolbar): add a reload button`. Types include `feat`, `fix`,
  `perf`, `test`, `docs`, `build` and `chore`.

AI-assisted contributions are welcome; VOMD itself is built with AI models (see the
README's [AI disclosure](README.md#ai-disclosure)). You're responsible for what you submit, though:
make sure you understand it and have tested it, and mention in the pull request that AI helped.
